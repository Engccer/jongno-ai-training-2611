3. Git 설치

Code 탭을 처음 열면 Git 설치 안내 대화상자가 자동으로 뜹니다. 대화상자 안의 Git 다운로드 버튼을 누르고, 내려받은 설치 파일을 실행해 모든 화면에서 기본 설정 그대로 Next 또는 Install을 눌러 끝까지 설치합니다.

「나중에」 버튼을 누르지 마세요. Git 없이 진행되어 다음 단계가 막힙니다.

설치가 끝나면 앱을 완전히 종료한 뒤 다시 실행합니다. Claude 앱은 창을 닫아도 백그라운드에 남으므로 작업 관리자로 끕니다.

  1. Ctrl+Shift+Esc로 작업 관리자를 엽니다.
  2. 가상 커서를 해제하고 목록을 내려가 Claude를 찾습니다.
  3. 팝업 키를 누르고 Alt+E를 눌러 작업을 끝냅니다.
  4. Windows 키를 눌러 검색창에 「클로드」를 입력하고 다시 실행합니다.

작업 관리자 조작이 번거로우면 컴퓨터를 껐다 켜도 됩니다.

챗봇에서 에이전트로

챗봇과 에이전트는 사용자의 지시를 처리하는 방식이 다름.

  • 챗봇: 대화창에서 질문에 답하고 초안을 작성함. 보고서 요약을 답변으로 받았다면 사용자가 그 내용을 업무 문서에 옮겨야 함.
  • 에이전트: 지정된 폴더에 직접 들어가 파일을 읽고, 문서를 편집하고, 결과 파일(.hwpx, .docx, .md, .csv 등)을 폴더에 저장함. 탐색기를 열어 보면 파일이 실제로 생성되어 있음.

이 차이가 사무 업무에서 중요한 이유:

  • 사무 업무는 화면 위의 대화로 끝나지 않음.
  • 받은 문서를 열어 검토하고, 서식을 채워 보고하고, 결과 파일을 정리해 보내야 비로소 끝남.
  • 에이전트에게는 초안 작성에 이어 실제 파일 작업까지 맡길 수 있음.

폴더와 파일을 중심으로 작업하기

에이전트가 읽는 자료와 만든 결과물은 컴퓨터의 폴더에 남음. 파일 탐색기로 같은 폴더를 열면 결과를 확인할 수 있고, 다른 에이전트에도 그 파일을 읽고 이어서 작업하도록 요청할 수 있음. 대화 내용이나 설정까지 자동으로 공유되는 것은 아니므로, 이어 할 일은 파일과 지시로 전달함.

Claude Desktop 앱의 Code 탭과 Claude Code CLI는 같은 작업 폴더를 다룰 수 있음. 터미널은 입력과 키패드 리뷰 중심으로 조작하고, Desktop 앱은 편집창·버튼·응답 영역을 오가며 조작함. 화면을 확대해서 읽는 편이 익숙하면 Code 탭을 사용해도 됨. 앱으로 진행할 때는 채팅이 아니라 코드를 선택함.

따라 하기 1: 터미널과 Claude Code 셋업하기

터미널, 셸, CLI 구분하기

  • 터미널: 텍스트를 입력하고 프로그램의 출력을 확인하는 앱임. 여기서는 Windows 터미널을 씀.
  • 셸: 입력한 명령을 해석하고 프로그램을 실행하는 도구임. 여기서는 PowerShell 7을 씀.
  • CLI: command line interface(명령 줄 인터페이스)의 약자임. Claude Code CLI는 터미널에서 명령으로 실행하는 에이전트임.

Windows 터미널을 열면 먼저 PowerShell이 실행되고, 거기에 claude를 입력하면 Claude Code가 실행됨. PowerShell에 명령을 입력하는 상태와 Claude에게 자연어로 지시하는 상태를 구분해야 함.

설치와 기본 설정 요청하기

Claude Desktop 앱 Code 탭이나 이미 실행할 수 있는 에이전트의 입력창에 다음을 보냄.

이 컴퓨터에 Windows 터미널과 PowerShell 7이 설치돼 있는지 확인해 줘. 없으면 설치하고, Windows 터미널을 기본 터미널 앱으로 설정해 줘. Windows 터미널의 기본 프로필은 PowerShell 7로 바꿔 줘.

Claude Code CLI를 공식 네이티브 설치 방식으로 설치해 줘. 이미 설치돼 있으면 설치 방식과 실제 실행되는 경로를 확인해 줘.
  • 네이티브 설치: Claude Code 실행 파일을 직접 설치하는 방식임. 공식 네이티브 설치는 자동 업데이트를 지원함.
  • 기본 터미널 앱과 기본 프로필은 서로 다름. 기본 터미널 앱은 명령 창을 어느 앱으로 열지, 기본 프로필은 그 안에서 어느 셸을 실행할지 정하는 설정임.
  • Windows PowerShell과 PowerShell 7은 별도 프로그램임. PowerShell 7을 설치했어도 기본 프로필은 Windows PowerShell로 남아 있을 수 있음.
  • 중복 설치 안내가 나온 경우: 어느 방식으로 설치한 Claude가 실행되는지 먼저 확인하도록 요청함. 설치됐다는 답만으로 끝내지 않고 새 터미널에서 직접 실행해 봄.

터미널에서 직접 실행하기

  1. Windows 터미널 열기: Windows 키를 누르고 wt를 입력한 뒤 Enter를 누름. 검색되지 않으면 Windows Terminal을 검색함.
  2. 셸 확인하기: 키패드로 시작 화면을 읽어 PowerShell 7인지 확인함. Windows PowerShell로 뜨면 설치를 맡긴 에이전트에서 기본 프로필을 PowerShell 7로 바꾸도록 요청한 뒤 터미널을 닫았다 다시 엶.

  3. 홈 디렉터리로 이동하기: 아직 Claude를 실행하지 않은 PowerShell 프롬프트에서 다음을 입력함. 터미널의 시작 폴더 설정이 달라도 같은 위치에서 실습할 수 있음.

    cd ~

  4. Claude Code 실행하기: 같은 PowerShell 프롬프트에 다음을 입력하고 Enter를 누름.

    claude

  5. 첫 실행 설정과 로그인하기: 테마 선택이 나오면 원하는 화면 색상을 고름. 로그인 방법에서는 Claude 구독 계정으로 로그인하는 항목을 선택하고, 열린 브라우저에서 인증한 뒤 터미널로 돌아옴. 이미 인증한 환경이면 이 화면이 생략될 수 있음.

  6. 폴더 확인하기: 폴더를 신뢰할지 묻는 화면이 나오면 현재 위치가 본인의 홈 디렉터리인지 확인함. y/n 형식이면 허용할 때 y를 입력하고 Enter를 누름.
  7. 응답 확인하기: 모델명과 입력창이 나타나면 간단한 질문을 보내 응답을 확인함. 이때부터 자연어 지시를 입력함.
  • claude를 찾을 수 없다고 나오는 경우: 설치 직후에는 새 실행 경로가 반영되지 않을 수 있음. 터미널을 닫았다 다시 열고, 그래도 안 되면 설치를 맡긴 에이전트에 오류 문구를 전달함.
  • 앱 안에서만 실행된 경우: Desktop 앱이 연 작업 화면과 별도로 Windows 터미널을 직접 열어 위 절차를 진행함. 터미널에서 Claude가 정상 실행되면 Desktop 앱을 닫아도 됨.

확인 방법: Windows 터미널에서 Claude를 실행하고 한국어 질문에 답을 받을 수 있어야 함.

따라 하기 2: 스크린 리더 모드 켜기

  • 문제: 터미널 화면에는 테두리 선이나 진행 애니메이션 같은 장식 문자가 포함되어 있어, 키패드로 탐색할 때 불필요한 음성이 많이 낭독됨.
  • 해결: Claude Code가 이를 평문으로 전환해 주는 전용 스크린 리더 모드(axScreenReader)를 기본 제공함.

터미널에서 실행한 Claude Code 입력창에 다음을 보냄.

클로드 코드 설정에서 스크린 리더 모드 켜 줘.
  • 「클로드 코드 설정에서」까지 입력해야 함. 이 말을 빼면 다른 접근성 설정과 혼동해 무엇을 켤지 고르라는 목록이 뜰 수 있음.
  • 고르라는 목록이 떴으면 목록에서 하나를 고르지 말고 위 문장을 그대로 다시 보냄.
  • 전역(Global) 설정으로 저장되므로, 한 번 켜 두면 터미널을 다시 열거나 다른 폴더에서 작업할 때도 유지됨.

확인 방법: 터미널을 닫고 따라 하기 1의 「터미널에서 직접 실행하기」대로 다시 열어 claude를 실행함. 시작 화면에 스크린 리더 모드가 켜져 있다는 안내가 나오면 적용된 것임. 키패드로 훑어 장식 문자가 사라졌는지도 함께 봄.

스크린 리더 모드에서는 선택지를 번호로 입력한 뒤 Enter로 확정하는 방식도 사용함. 화면의 번호와 항목을 먼저 읽고 입력함.

터미널에서 Claude 다루기

터미널은 조작 체계가 단순한 대신 화면을 훑는 방법이 앱과 다름.

입력창은 맨 아래에 있음

  • 채팅창과 같은 구조임. 입력창이 화면 맨 아래고, 그 가까이에 권한 모드 줄이 있음.
  • 커서가 입력창에 있어도 센스리더가 위쪽 내용을 읽고 있을 때가 있음. 입력하기 전에 아래 화살표를 두어 번 누름.
  • 선택 목록이 떠 있을 때는 화살표를 누르지 않음. 화살표가 고른 항목을 바꿈. 목록의 항목은 번호나 문자를 입력한 뒤 Enter로 고름.

키패드로 지난 응답 읽기

  • 위아래 화살표로는 읽히지 않음. Ctrl+넘패드 2로 맨 아래로 간 뒤 위로 올라가며 읽음.
  • 한 줄씩 위아래로만 오가면 되므로 익으면 단순함. 점자 디스플레이를 연결하면 훨씬 빠름.

선택지 입력 후 Enter 누르기

  • 숫자든 y든 n이든 누르고 Enter를 쳐야 넘어감. 스크린 리더 모드에서는 Enter로 확정하는 방식이 기본임.
  • 입력 후 화면이 바뀌지 않으면 Enter를 눌렀는지 확인함.

Shift+Tab으로 권한 모드 바꾸기

  • Shift+Tab을 누를 때마다 권한 모드가 바뀌며, 현재 모드는 입력창 가까이에 표시됨. 기본 모드(default), 편집 자동 승인(acceptEdits), 계획 모드(plan)가 있고, 계정과 설정에 따라 자동 모드(auto) 등이 추가됨.
  • 편집 자동 승인은 파일 편집을 자동으로 허용하는 설정임. 자동 모드는 도구 실행을 검토해 허용 여부를 판단함. 자동 모드에서도 작업이 차단되거나 멈출 수 있으므로 마지막 응답을 확인해야 함.

작업 중 진행 줄의 반복 낭독 줄이기

작업 시간이 갱신되면서 같은 줄이 반복 낭독될 수 있음. 다음 방법 중 하나로 줄임.

  • 지시를 보낸 뒤 다른 창으로 포커스를 옮기고 끝나기를 기다림.
  • 점자 디스플레이를 연결함. 음성 낭독과 별개로 점자로 내용을 확인할 수 있음.
  • 음성만 잠시 끔.

영어로 표시되는 작업 과정 읽기

에이전트의 작업 과정이 영어로 길게 표시될 수 있음. 작업 결과는 요약으로 확인하고, 상세 과정이 필요할 때 키패드로 위쪽 내용을 읽음.

터미널 창과 새 대화 열기

  • Ctrl+Shift+T로 새 탭을 엶. 안 되면 Ctrl+Shift+숫자 1.
  • 둘 다 안 되면 처음처럼 wt로 새 창을 엶. 여러 창을 함께 열 수 있음.
  • 대화를 새로 시작하려면 /exit로 Claude Code를 종료한 뒤, PowerShell 프롬프트에서 claude를 다시 실행함.

따라 하기 3: 파일 탐색기에서 작업 폴더 열기

파일 탐색기에서 작업할 폴더를 연 뒤 터미널을 실행하면, 그 위치에서 Claude에게 일을 맡길 수 있음.

자주 쓰는 폴더 고정하기

  1. 파일 탐색기 열기: Windows 키+E를 누름.
  2. 고정할 폴더 선택하기: 연습 폴더의 상위 폴더로 이동해 목록에서 「연습」 폴더를 선택함.
  3. 고정하기: 팝업 키 또는 Shift+F10을 누르고 폴더를 즐겨찾기나 빠른 실행에 고정하는 항목을 선택함. 메뉴 이름은 Windows 버전에 따라 다를 수 있음.
  4. 탐색 창으로 이동하기: 파일 목록에서 Shift+Tab을 눌러 왼쪽의 트리뷰로 이동함. 원하는 영역이 아니면 F6으로 영역을 순환함.
  5. 고정한 폴더 열기: 방향키나 폴더 이름의 첫 글자로 「연습」을 찾아 Enter를 누름. Tab으로 파일 목록으로 돌아와 내용이 맞는지 확인함.

업무 폴더, 홈 디렉터리처럼 자주 여는 곳도 같은 방법으로 고정할 수 있음.

초점을 잃었을 때와 탭 전환하기

  • 영역 이동: F6을 누르면 탐색 창, 파일 목록 등 주요 영역을 순환함. Tab으로 여러 버튼을 지나가다 현재 위치를 놓쳤을 때 사용함.
  • 새 탭: Ctrl+T를 누름. 폴더 여러 개를 한 탐색기 창에 열 수 있음.
  • 다음·이전 탭: Ctrl+Tab, Ctrl+Shift+Tab을 누름.
  • 현재 탭 닫기: Ctrl+W를 누름. 마지막 탭이면 탐색기 창이 닫힘.

연습 폴더에서 터미널 열기

  1. 연습 폴더로 들어가기: 파일 목록에 실습에 쓸 PDF·한글 문서가 보이는지 확인함.
  2. 파일 선택 해제하기: 파일 하나가 선택돼 있으면 Ctrl+Space를 눌러 「선택 안 됨」 상태인지 확인함. 초점은 파일 목록에 남음.
  3. 폴더의 메뉴 열기: 팝업 키 또는 Shift+F10을 누름. 파일 하나에 대한 메뉴가 아니라 현재 폴더의 메뉴인지 확인함.
  4. 터미널 열기: 터미널에서 열기를 선택함. 메뉴에 Alt+T가 안내되면 그 키로 선택할 수도 있음.
  5. 위치 확인 후 실행하기: PowerShell 프롬프트에 연습 폴더 경로가 표시되는지 확인하고 claude를 입력함.
  6. 첫 파일 지시 보내기: 폴더 신뢰 확인을 마친 뒤 Claude 입력창에 다음을 보냄.
    이 폴더에 어떤 파일이 있는지 읽고 정리해 줘.

확인 방법: 답변의 파일 이름과 탐색기에 있는 파일 이름이 일치해야 함. 파일 경로를 정확히 지정하려면 탐색기에서 파일을 선택하고 Ctrl+Shift+C로 경로를 복사해 Claude 입력창에 붙여넣음.

선택한 폴더는 작업의 기준 위치임. 폴더 지정만으로 그 밖의 접근이 모두 차단되는 것은 아니며, 실제 접근·실행 권한은 별도 설정으로 관리함.

여러 창을 가상 데스크톱으로 나누기

  • Ctrl+Windows 키+D: 가상 데스크톱 추가
  • Ctrl+Windows 키+좌우 방향키: 데스크톱 사이 이동
  • Ctrl+Windows 키+F4: 현재 데스크톱 닫기

브라우저와 메신저는 한쪽에, 파일 탐색기와 터미널은 다른 쪽에 두면 Alt+Tab으로 오갈 창이 줄어듦. 다른 데스크톱으로 이동해도 실행 중인 작업은 계속됨.

홈 디렉터리와 Claude 설정 폴더

홈 디렉터리는 현재 Windows 사용자의 기본 폴더임. 경로는 C:\Users\[본인 계정 이름]이며, 탐색기에서는 Users가 「사용자」로 표시될 수 있음. 계정 이름은 컴퓨터마다 다름.

  1. 파일 탐색기를 열고 내 PC, 로컬 디스크(C:), 사용자로 차례로 들어감.
  2. 공용이 아니라 본인 계정 이름의 폴더를 엶.
  3. 그 안에서 .claude 폴더를 찾음. 맨 앞의 점도 폴더 이름의 일부임.
  4. .claude 안의 skills 폴더를 확인함. 전역 스킬을 아직 설치하지 않았다면 없을 수 있음.
  • .claude: Claude Code의 사용자 설정과 관련 파일이 모이는 폴더임.
  • .claude\skills: 여러 작업 폴더에서 쓸 개인 스킬의 위치임.
  • 작업 폴더의 .claude\skills: 해당 프로젝트에서 쓸 스킬을 두는 위치임. 홈 디렉터리에 있는 것과 범위가 다름.

설정과 스킬을 확인할 때는 홈 디렉터리를, 실제 문서를 다룰 때는 그 문서가 있는 작업 폴더를 엶. 채팅이나 코워크에서 추가한 스킬과 로컬에 설치한 스킬은 저장·로딩 방식이 다르므로, 확인할 때는 Claude Code에 설치된 스킬을 지정함.

따라 하기 4: 시각장애인을 위한 스킬 번들 설치하기

    skills-for-the-blind에 포함된 다섯 스킬이 모두 설치돼 있는지 확인하고, 각각 어떤 일을 할 수 있는지 알려 줘.

확인 방법: 폴더가 있는지와 새 대화에서 스킬을 찾는지를 함께 확인함. 폴더만 보인다고 음성 출력이나 문서 변환에 필요한 설정까지 끝난 것은 아님. TTS 요약 설정과 각 도구의 점검은 2회기에서 진행함.

따라 하기 5: SKILL.md를 메모장에서 읽기

스킬은 폴더 안에 SKILL.md가 있는 구조임. SKILL.md에는 에이전트가 따를 설명과 절차가 들어 있고, 필요한 참고 자료나 실행 프로그램이 같은 폴더에 함께 들어갈 수 있음.

메모장에서 구문 보기로 바꾸기

마크다운(.md)은 텍스트에 기호를 붙여 제목·목록·강조 등을 표시하는 문서 형식임. SKILL.md도 이 형식으로 작성됨.

파일 탐색기에서 SKILL.md를 찾아 Enter를 누름. 마크다운 파일을 처음 여는 것이면 앱을 고르라는 화면이 뜨므로 메모장을 선택함.

마크다운을 지원하는 메모장에는 포맷 보기와 구문 보기가 있음. 포맷 보기는 제목과 강조를 서식으로 표시하고, 구문 보기는 원래 기호를 그대로 보여 줌. 센스리더로 내용이 읽히지 않으면 구문 보기로 바꿈.

  1. 메뉴 열기: 메모장에서 Alt를 누름. 파일, 편집, 보기 메뉴가 뜸.
  2. 마크다운 메뉴로 이동하기: 보기로 들어가 마크다운을 찾고 Enter를 누름.
  3. 구문 보기 선택하기: 포맷과 구문 중 구문을 고름.
  • 마크다운 메뉴는 .md 파일을 열었을 때 나타남. 메모장 버전에 따라 메뉴가 없으면 일반 텍스트로 읽으면 됨. 구문은 영어로 syntax임.
  • 방향키를 눌러도 읽히지 않는 경우: 메모장에서 Ctrl+T로 새 탭을 열고 Ctrl+F4로 그 탭을 닫은 뒤 원래 문서를 다시 탐색함.

  3. 폴더 신뢰하기: 처음 여는 폴더면 신뢰를 묻는 화면이 뜸. 본인이 준비한 연습 폴더가 맞는지 확인하고 신뢰 버튼을 누름.

작업 범위와 권한 관리

  • 작업 범위: 선택한 폴더를 기준으로 파일을 읽고 작업함. 폴더 지정만으로 그 밖의 접근이 모두 차단되는 것은 아님. 실제 접근·실행 권한은 별도 설정으로 관리함.
  • 승인 요청이 뜬 경우: 대상 파일과 실행할 명령을 확인하고 허용 여부를 결정함. 폴더 밖 접근이나 프로그램 설치도 현재 권한 설정에 따라 승인 요청이 뜰 수 있음.
  • 자동 모드: 실행하려는 작업을 자동으로 검토해 승인 요청을 줄이는 설정임. 프롬프트 편집창 아래의 편집 수락 풀다운 메뉴에서 자동을 선택하고, 확인 창에서 자동 모드 활성화를 누름.
  • 수동 승인: 파일 편집이나 명령 실행 때 승인 요청이 뜨면 내용을 확인하고 응답해야 작업이 계속됨.

자동 모드가 보이지 않는 경우: 앱 업데이트 상태와 계정·조직의 설정을 확인해야 함.

설치가 실패할 때

스킬 설치 명령은 Node.js에 포함된 npx로 실행됨. 설정 점검 스크립트는 Python을 씀. 음성 재생은 Windows PowerShell과 내장 음성을 씀. 이 가운데 하나가 없으면 설치나 설정이 멈춤. 필요한 도구의 설치와 설정을 에이전트에게 맡김.

이런 개발 환경 설정은 내가 잘 모르니, 필요한 건 네가 알아서 설치하고 설정까지 끝내 줘. 무료 프로그램만 설치하고, 설치 전에 무엇을 설치할지 알려 줘.

규칙 파일과 스킬

에이전트에게 반복해서 알려 줄 내용은 두 가지 파일에 적어 둠.

  • 규칙 파일(CLAUDE.md): 한 폴더에서 늘 지킬 규칙과 폴더 설명을 적음. 그 폴더에서 Claude를 시작하면 매번 읽음.
  • 스킬: 반복 작업의 절차를 묶은 것임. 지침 파일 SKILL.md에 절차를 적고, 필요한 참고 자료와 실행 스크립트를 함께 둠. 할 일이 스킬의 설명과 맞으면 에이전트가 그 스킬을 꺼내 씀.

스킬은 직접 만들거나 공개된 것을 설치할 수 있음. 설치한 뒤에는 스킬 이름과 할 일을 함께 입력하면 확실하게 그 스킬을 씀.

  • 사용자 폴더에 둔 스킬: 홈 디렉터리의 .claude\skills에 둔 스킬은 어느 작업 폴더에서나 쓸 수 있음. 오늘 설치하는 스킬이 여기에 들어감.
  • 작업 폴더에 둔 스킬: 작업 폴더의 .claude\skills에 둔 스킬은 그 폴더에서만 씀.

  • 길고 복잡한 작업: 여러 단계를 진행하는 동안 목표와 작업 규칙을 일관되게 참고하는 데 도움이 됨.

  • 하위 폴더의 파일에는 그 업무에만 해당하는 구체적인 내용이 들어감.

폴더 구성을 바꾸면 기존 설명과 실제 파일 배치가 달라질 수 있음. 작업을 마친 뒤 입력창에 다음을 보냄.

  • 회사 컴퓨터에서 설치가 거부되는 경우: 관리자 권한이 필요한 설치는 회사 전산 담당에 요청함.

Gemini API 키 등록하기

docparse의 Gemini 파서와 speech-toolkit의 Gemini 음성은 GEMINI_API_KEY라는 환경 변수에서 키를 읽음. 환경 변수는 여러 프로그램이 읽을 수 있도록 설정값을 Windows에 저장해 두는 장치임.

키는 비밀번호와 같음. 다음 두 가지를 지킴.

  • 키를 Claude 입력창에 붙여넣지 않음. 대화 내용은 Claude 서비스로 전송되고 이 컴퓨터의 대화 기록 파일에도 남음. 키 값은 아래 창에 직접 입력함.
  • 이미 붙여넣었다면 그 키를 폐기함. Google AI Studio에서 그 키를 삭제하고 새 키를 발급받아 다시 등록함.

등록 절차

  1. 환경 변수 창 열기: Windows 키를 누르고 「환경 변수」를 입력함. 검색 결과에서 계정의 환경 변수 편집을 고르고 Enter를 누름. 검색으로 찾지 못하면 Claude에게 창을 열어 달라고 요청함.

    계정의 환경 변수 편집 창을 열어 줘. 키 값은 내가 직접 입력할게.

  2. 새 변수 만들기: 위쪽 사용자 변수 목록 아래의 새로 만들기 버튼을 누름. 아래쪽 시스템 변수의 같은 이름 버튼과 헷갈리지 않도록 Tab으로 이동하며 확인함.

  3. 이름과 값 입력하기: 변수 이름 칸에 GEMINI_API_KEY를 입력함. 변수 값 칸에 메모장에 복사해 둔 키를 붙여넣음. 확인을 누름.
  4. 창 닫기: 환경 변수 창의 확인을 눌러 닫음.
  5. 터미널 다시 열기: 열려 있는 터미널을 모두 닫고 연습 폴더에서 터미널을 다시 연 뒤 claude를 실행함. 환경 변수는 새로 연 터미널부터 읽힘.

확인 방법: 키 값을 화면에 내지 않고 등록 여부만 확인하도록 요청함.

GEMINI_API_KEY 환경 변수가 등록돼 있는지 확인해 줘. 키 값은 화면에 출력하지 말고 있는지 없는지만 알려 줘.
  • 무료 티어의 조건: 무료 사용 한도와 데이터 처리 조건은 Google AI Studio에서 확인해야 함.
  • 결제 설정: 키를 만든 프로젝트에 결제 설정이 연결돼 있으면 요금이 나갈 수 있음. 결제 설정이 없는 프로젝트의 키를 씀.
  • 실습 자료: 개인정보나 대외비가 담긴 문서는 실습에 쓰지 않음.
  • 키를 메모장에 남겨 둔 경우: 등록을 마쳤으면 메모장의 키를 지우고 저장하지 않고 닫음.

원본 파일이 따로 있으면 그것을 읽음

배포용 PDF는 대개 한글·워드 문서를 변환한 것임. 같은 문서의 원본 파일이 있으면 그 파일을 파싱하는 편이 정확함. 원본에는 표의 칸 구조와 제목 단계가 그대로 들어 있어 파서가 추측할 부분이 줄어듦. docparse는 PDF를 받으면 원본 파일이 있는지 먼저 확인하도록 되어 있음.

막히는 곳

  • 스캔 PDF인 경우: docparse는 스캔 문서에 글자 인식(OCR) 파서(LlamaParse, Upstage 등)를 쓰도록 되어 있음. 이 파서들은 별도 API 키가 필요해 Gemini 키만으로는 처리되지 않음. LlamaParse는 월 무료 크레딧이 있으므로 쓰려면 키를 따로 발급함. 무료 한도는 제공자 정책에 따라 바뀌므로 발급 때 확인함.

  • 필요한 도구가 없다는 응답이 나온 경우: 설치할 항목을 설명하도록 요청함.

    이 문서를 처리하는 데 필요한 무료 도구와 설정 항목을 알려 줘. 내가 확인하면 설치와 설정을 진행해 줘. API 키는 값을 대화에 쓰지 않고 설정할 수 있는 방법을 안내해 줘.

  • 워드 문서를 준비한 경우: 워드(.docx) 파일도 같은 지시문으로 파싱할 수 있음. 컴퓨터 안에서 도는 무료 파서가 처리함.

따라 하기 11: abridge로 긴 문서 줄이기

  • 문제: 일반 AI 요약은 문장을 새로 써서 원문의 어투가 사라지고, 불릿 나열로 평평해짐. 무엇이 원문이고 무엇이 AI의 해석인지 구분하기 어려움.

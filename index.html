3. Git 설치

1회차 전에 마쳐 주세요.

Code 탭을 처음 열면 Git 설치 안내 대화상자가 자동으로 뜹니다. 대화상자 안의 Git 다운로드 버튼을 누르고, 내려받은 설치 파일을 실행해 모든 화면에서 기본 설정 그대로 Next 또는 Install을 눌러 끝까지 설치합니다.

「나중에」 버튼을 누르지 마세요. Git 없이 진행되어 다음 단계가 막힙니다.

  • 안내가 뜨지 않으면 Git이 이미 설치된 것이므로 4번으로 넘어갑니다.
  • 다운로드가 진행되지 않으면 다운로드 페이지 열기를 누릅니다. 브라우저가 열리지 않으면 다운로드 폴더에 설치 파일이 있는지 확인해 실행합니다.
  • Git을 설치하기 전에는 프롬프트 입력창이 비활성 상태입니다.

설치가 끝나면 앱을 완전히 종료한 뒤 다시 실행합니다. Claude 앱은 창을 닫아도 백그라운드에 남으므로 작업 관리자로 끕니다.

  1. Ctrl+Shift+Esc로 작업 관리자를 엽니다.
  2. 가상 커서를 해제하고 목록을 내려가 Claude를 찾습니다.
  3. 팝업 키를 누르고 Alt+E를 눌러 작업을 끝냅니다.
  4. Windows 키를 눌러 검색창에 「클로드」를 입력하고 다시 실행합니다.

작업 관리자 조작이 번거로우면 컴퓨터를 껐다 켜도 됩니다.

확인: 다시 실행한 뒤 Code 탭으로 돌아와 하단 입력창에 아래 문장을 그대로 붙여넣고 보냅니다.

Git 설치를 마쳤는데 제대로 설치된 것인지 확인해 줘.

Claude가 확인을 위해 PowerShell 명령을 실행하겠다며 권한을 묻습니다. 항상 허용을 누르세요. 같은 종류의 명령을 다시 묻지 않는 설정입니다. 설치가 확인됐다는 답이 오면 된 것입니다.

환경 변수를 설정해야 한다는 안내가 나오면(CLAUDE_CODE_GIT_BASH_PATH 등) 시스템 설정 창을 직접 건드리지 마시고 입력창에 아래 한 줄을 보내세요. 안내에 붙은 번호는 달라질 수 있으므로 번호 대신 방법 이름으로 지시합니다.

PowerShell로 환경 변수를 영구 설정하는 방법으로 네가 바로 해 줘.

「현재 세션의 PATH에는 아직 반영되지 않았다」는 안내가 나와도 같은 방법으로 앱을 다시 실행합니다.

환경 변수 설정이 끝나면 위와 같은 방법으로 앱을 한 번 더 종료하고 다시 실행합니다.

5. 홈 디렉터리에 project 폴더 만들기

1회차 전에 마쳐 주세요.

홈 디렉터리에 폴더를 하나 만들고 이름을 「project」로 붙입니다. Windows에서 홈 디렉터리는 C:\Users\<본인 계정 이름>이며, 파일 탐색기에는 「사용자」 폴더 아래 본인 계정 이름으로 표시됩니다. 파일 탐색기에서 Alt+D로 주소창에 이동해 %USERPROFILE%을 입력하고 Enter를 누르면 바로 열립니다.

project 폴더 안에는 다음 두 파일을 넣어 주세요.

  • 업무에서 받은 PDF 문서 한 개(공문, 안내문, 보고서 등)
  • 업무에서 다루는 한글 문서 한 개(한글 문서가 없으면 워드 문서)

이름·연락처·주민등록번호 같은 개인정보가 들어 있지 않은 문서로 골라 주세요.

Claude에서 이 폴더를 처음 고르면 폴더를 신뢰할지 묻는 화면이 뜹니다. 신뢰 버튼을 누르셔야 그 폴더의 파일을 읽습니다.

Desktop 앱에서 이 폴더로 작업하려면: 화면 확대가 익숙하시면 터미널 대신 Code 탭을 써도 됩니다.

  1. Code 탭에서 편집창 위쪽의 로컬 폴더를 고르고 Enter를 누릅니다.
  2. 홈 디렉터리의 project 폴더로 이동해 폴더 선택을 누릅니다.
  3. 입력창 상단에 project 폴더 이름이 표시되는지 확인합니다.
  4. 신뢰를 물으면 본인이 준비한 폴더인지 확인하고 신뢰를 누릅니다.
  5. 폴더 밖 접근이나 프로그램 설치처럼 승인을 묻는 작업은 대상 파일과 명령을 확인하고 응답합니다. 편집창 아래 편집 수락 메뉴에서 자동을 고르고 자동 모드 활성화를 누르면 승인 요청이 줄어듭니다. 자동 모드가 보이지 않으면 앱을 업데이트합니다.

  • 작업 중: 진행 줄이 계속 바뀌면 다른 창에서 기다립니다.
  • 설치 실패: 「인식되지 않습니다」 같은 오류가 나오면 필요한 도구가 없는 것입니다. 설치에는 Node.js의 npx, 설정 점검에는 Python, 재생에는 Windows PowerShell과 내장 음성을 씁니다. 아래 문장으로 설치와 설정을 함께 맡깁니다.

10. Gemini API 키 발급과 등록

발급은 2회차 전에 마쳐 주세요. 등록은 2회차 수업에서 함께 합니다.

문서 파싱과 음성 변환 실습에 씁니다. 결제 정보를 등록하지 않은 키는 무료 범위 안에서만 쓰이므로 요금이 나가지 않습니다.

키는 비밀번호와 같습니다. 다른 사람과 공유하지 마시고, 화면에 띄워 둔 채 자리를 비우지 마세요. Claude 입력창에도 붙여넣지 않습니다.

발급

https://aistudio.google.com/apikey

Google 계정으로 로그인한 뒤 API 키를 만들고, 발급된 키를 메모장 등에 복사해 둡니다.

등록

  1. Windows 키를 누르고 「환경 변수」를 검색합니다.
  2. 계정의 환경 변수 편집을 고르고 Enter를 누릅니다. 검색되지 않으면 Claude에게 아래 문장을 보냅니다.
계정의 환경 변수 편집 창을 열어 줘. 키 값은 내가 직접 입력할게.
  1. 위쪽 사용자 변수 목록 아래의 새로 만들기 버튼을 누릅니다. 아래쪽 시스템 변수의 같은 이름 버튼과 혼동하지 않도록 Tab으로 위치를 확인합니다.
  2. 변수 이름에 GEMINI_API_KEY를 입력합니다.
  3. 변수 값에 복사해 둔 키를 붙여넣고 확인을 누릅니다.
  4. 환경 변수 창의 확인을 눌러 닫습니다.
  5. 터미널을 모두 닫고 project 폴더에서 다시 열어 claude를 실행합니다.
  6. 키 값을 출력하지 않고 등록 여부만 확인해 달라고 요청합니다.
GEMINI_API_KEY 환경 변수가 등록돼 있는지 확인해 줘. 키 값은 화면에 출력하지 말고 있는지 없는지만 알려 줘.

등록을 마치면 메모장의 키를 지우고 저장하지 않고 닫습니다. 키가 대화에 노출됐다면 Google AI Studio에서 그 키를 삭제하고 새로 발급받으세요.

다른 서비스의 API 키(ElevenLabs, Azure 등)도 같은 방법으로 등록합니다. 변수 이름만 다릅니다.

14. gh CLI 설치와 인증

3회차 전에 마쳐 주세요. 3회차 실습은 인증 없이도 진행할 수 있지만, 4회차 전에는 마쳐야 합니다.

gh CLI는 터미널에서 GitHub를 다루는 도구입니다. 한 번 인증해 두면 저장소를 만들고 파일을 올리는 일을 Claude가 대신합니다. 브라우저에서 GitHub에 로그인했더라도 gh 인증은 따로 해야 합니다. 인증은 Claude를 거치지 않고 터미널에 직접 입력하는 것이 가장 간단합니다.

Claude에게 설치와 인증 진행을 맡길 수도 있습니다(선택). 로그인과 코드 입력은 본인이 직접 합니다.

GitHub CLI(gh)를 설치하고 내 GitHub 계정으로 인증하는 과정을 진행해 줘. 웹 브라우저 로그인이나 인증 코드 입력처럼 내가 직접 할 단계에서는 멈추고 알려 줘.

설치

  1. Windows 키를 누르고 wt를 입력한 뒤 Enter를 눌러 Windows Terminal을 엽니다. 이미 열려 있으면 Ctrl+Shift+N, Ctrl+Shift+T를 차례로 눌러 새 탭을 엽니다. Claude를 실행하지 않은 PowerShell 상태에서 진행합니다.
  2. 아래 명령을 입력합니다.
winget install GitHub.cli

약관 동의를 물으면 Y를 입력하고 Enter를 누릅니다. 관리자 권한 확인 창이 뜨면 허용합니다. winget을 찾지 못한다는 오류가 나오면 아래 주소에서 Windows용 설치 파일을 내려받아 실행하세요.

https://cli.github.com
  1. 설치가 끝나면 exit를 입력해 터미널을 닫고 새로 엽니다. 설치 전에 열어 둔 터미널은 gh 명령을 인식하지 못할 수 있습니다.
  2. 아래 명령으로 설치를 확인합니다. 버전이 나오면 설치된 것입니다.
gh --version

인증

  1. 아래 명령을 입력합니다.
gh auth login --clipboard
  1. 질문이 몇 가지 나옵니다. 묻는 순서는 gh 버전에 따라 다를 수 있으니 질문 내용을 듣고 아래 표에서 답을 찾으세요. 센스리더 키패드로 화면을 읽고, 일반 방향키로 항목을 고른 뒤 Enter로 확정하세요. 원하는 항목이 이미 선택돼 있으면 Enter만 누르면 됩니다. Y로 답하는 질문은 Y를 입력하고 Enter를 누릅니다.
질문 고를 항목
사용할 서비스 GitHub.com
Git 연결 방식 HTTPS
Git에도 GitHub 계정 인증을 쓸지 Y
로그인 방법 Login with a web browser
  1. 터미널에 일회용 인증 코드가 나오고 클립보드에 자동으로 복사됩니다. 메모장에 붙여넣어 코드가 들어왔는지 확인해 두세요.
  2. 터미널로 돌아와 Enter를 누르면 브라우저에 GitHub 화면이 열립니다.
  3. 표시된 계정이 본인 계정인지 확인하고 계속 진행합니다.
  4. 가상 커서를 끄고 코드 입력란의 첫 칸에 코드를 붙여넣습니다. 나머지 칸이 채워지지 않으면 한 글자씩 입력합니다.
  5. 접근 권한을 승인합니다. 완료 메시지가 나오면 터미널로 돌아갑니다.

확인: 터미널에 아래 명령을 입력합니다. 본인 계정이 로그인 상태로 나오면 된 것입니다.

gh auth status

막히는 경우

  • 명령을 입력했는데 웹 검색 결과가 뜨는 경우: Windows 검색창에 입력한 것입니다. Windows 검색창에는 wt만 입력하고, 설치와 인증 명령은 열린 PowerShell에 입력합니다.
  • 설치했는데 gh 명령을 찾지 못하는 경우: 터미널을 닫고 새로 연 뒤 gh --version을 입력합니다.
  • PowerShell에 한국어 지시를 입력해 오류가 난 경우: 한국어 지시는 claude를 실행한 뒤 입력합니다. gh auth login --clipboard는 PowerShell에 직접 입력하는 명령입니다.
  • 선택 항목이 읽히지 않는 경우: 선택 표시가 읽히지 않으면 센스리더 구두점 읽기 토글(Alt+Shift+Z)을 「모두 읽기」라고 들릴 때까지 누릅니다. 인증을 마치면 같은 키로 원래 설정으로 되돌립니다.
  • 코드가 클립보드에 복사되지 않은 경우: 키패드로 코드가 있는 줄(First copy your one-time code)을 읽고 센스리더 Insert+X로 마지막 음성 출력 내용을 복사합니다. 메모장에 붙여넣어 코드만 남기고 다시 복사합니다.
  • 브라우저가 열리지 않거나 GitHub에 로그인하지 않은 브라우저가 열린 경우: 13번에서 로그인한 브라우저에 아래 주소를 직접 입력합니다.
https://github.com/login/device
  • 인증 코드 오류나 만료 메시지가 나온 경우: 터미널에서 Ctrl+C로 취소하고 gh auth login --clipboard부터 다시 해서 새 코드를 받습니다.
  • Claude가 인증 대기 중 시간 초과를 알린 경우: 별도 PowerShell에서 직접 인증하고 gh auth status로 확인한 뒤 Claude로 돌아갑니다.
  • 어느 단계인지 알 수 없는 경우: Alt+PrintScreen으로 창을 캡처하고, 터미널 새 탭에서 claude를 실행해 입력창에 Alt+V로 붙여넣어 상황을 묻습니다.

끝까지 되지 않으면 어디서 멈췄는지 적어 두셨다가 강의 시간에 알려 주세요.

  • 다른 에이전트에도 같은 파일을 읽고 작업을 이어 가도록 요청할 수 있음.

  • 대화와 설정은 자동 공유되지 않으므로 이어 할 일은 파일과 지시로 전달함.

  • Claude Desktop 앱의 Code 탭과 Claude Code CLI는 같은 폴더를 다룰 수 있음.

  • 터미널은 입력과 키패드 리뷰로, Desktop 앱은 편집창·버튼·응답 영역을 오가며 조작함.
  • 화면 확대가 익숙하면 Desktop 앱에서 코드를 선택해 사용해도 됨( 참조).

세 용어의 차이

  • 터미널: 텍스트로 입력과 출력을 주고받는 앱(Windows 터미널).
  • 셸: 명령을 해석하고 프로그램을 실행하는 도구(PowerShell 7).
  • CLI: command line interface(명령 줄 인터페이스)의 약자.

  • Claude Code CLI는 터미널에서 명령으로 실행하는 에이전트임.

  • Windows 터미널에서 PowerShell이 열리면 claude를 입력해 Claude Code를 실행함.

  • PowerShell의 명령 입력과 Claude의 자연어 지시를 구분해야 함.

설치와 설정에 나오는 용어

  • 네이티브 설치: 실행 파일을 직접 설치하며 자동 업데이트를 지원함.
  • 기본 터미널 앱: 명령 창을 열 앱을 정함.
  • 기본 프로필: 터미널 안에서 실행할 셸을 정함.
  • Windows PowerShell과 PowerShell 7은 별도 프로그램이므로 설치 후 기본 프로필도 확인함.

스크린 리더 모드

  • 터미널의 테두리·진행 애니메이션은 키패드 탐색 시 불필요한 음성으로 낭독됨.
  • Claude Code의 스크린 리더 모드(axScreenReader)로 장식 문자를 줄일 수 있음.
  • 전역(Global) 설정으로 저장되므로, 한 번 켜 두면 터미널을 다시 열거나 다른 폴더에서 작업할 때도 유지됨.

홈 디렉터리

  • 홈 디렉터리: 현재 Windows 사용자의 기본 폴더(C:\Users\[본인 계정 이름]).
  • 탐색기에서는 Users가 「사용자」로 표시될 수 있음.

설정 폴더와 작업 폴더

  • .claude: Claude Code의 사용자 설정과 관련 파일이 모이는 폴더임.
  • .claude\skills: 여러 작업 폴더에서 쓸 개인 스킬의 위치임.
  • 작업 폴더의 .claude\skills: 해당 프로젝트에서만 쓸 스킬의 위치임.
  • 작업 폴더: 읽거나 편집할 문서와 결과물을 모아 두는 곳이며, 이번 실습에서는 홈 디렉터리의 「project」 폴더를 사용함.
  • 파일 탐색기에서 작업 폴더를 열고 터미널을 실행하면 그 위치에서 Claude에게 일을 맡길 수 있음.
  • 작업 폴더 밖의 접근까지 차단하려면 접근·실행 권한을 별도로 설정해야 함.

스킬과 SKILL.md

  • 스킬 폴더의 SKILL.md에는 에이전트가 따를 설명과 절차가 들어 있음.
  • 참고 자료나 실행 프로그램이 같은 폴더에 함께 들어갈 수 있음.
  • 파일 앞부분의 name은 스킬 이름, description은 어떤 작업에 쓰는 스킬인지 설명하는 항목임.

입력창은 맨 아래에 있음

  • 입력창은 화면 맨 아래에 있고, 그 가까이에 권한 모드가 표시됨.
  • 센스리더가 위쪽 내용을 읽고 있다면 입력 전에 아래 화살표를 두어 번 누름.
  • 선택 목록에서는 화살표가 항목을 바꾸므로, 번호나 문자를 입력하고 Enter로 고름.

키패드로 지난 응답 읽기

  • 위아래 화살표 대신 Ctrl+넘패드 2로 맨 아래로 간 뒤 키패드로 위쪽 응답을 읽음.
  • 점자 디스플레이를 연결하면 빠르게 확인할 수 있음.

선택지 입력 후 Enter 누르기

  • 스크린 리더 모드에서는 숫자·y·n을 입력한 뒤 Enter로 확정함.
  • 입력 후 화면이 바뀌지 않으면 Enter를 눌렀는지 확인함.

Shift+Tab으로 권한 모드 바꾸기

  • Shift+Tab으로 권한 모드를 바꾸고 입력창 근처에서 현재 모드를 확인함.
  • 기본 모드(default), 편집 자동 승인(acceptEdits), 계획 모드(plan)를 선택할 수 있음.
  • 계정·설정에 따라 자동 모드(auto) 등이 추가됨.
  • 편집 자동 승인은 파일 편집을 허용하고, 자동 모드는 도구 실행을 검토해 허용 여부를 판단함.
  • 자동 모드에서도 작업이 멈출 수 있으므로 마지막 응답을 확인함.

진행 줄의 반복 낭독

    • 다른 창에서 작업이 끝나기를 기다림.
    • 점자 디스플레이로 확인함.
    • 음성만 잠시 끔.

영어로 표시되는 작업 과정 읽기

새 탭과 새 대화 열기

  • Ctrl+Shift+T로 새 탭을 엶(안 되면 Ctrl+Shift+숫자 1).
  • Ctrl+Shift+T는 센스리더의 「제목줄 읽기」, Ctrl+Shift+1은 「사용자 윈도우 읽기」와 겹치므로 기능키 무시(Ctrl+Shift+N)를 한 번 누른 뒤 누름.
  • 둘 다 안 되면 wt로 새 창을 엶.
  • 대화를 새로 시작하려면 /exit로 Claude Code를 종료한 뒤, PowerShell 프롬프트에서 claude를 다시 실행함.

홈 디렉터리와 설정 폴더 확인하기

  3. 그 안에서 .claude 폴더를 찾음(맨 앞의 점 포함).
  4. .claude 안의 skills 폴더를 확인함(전역 스킬 설치 전에는 없을 수 있음).

  1. 파일 탐색기에서 Alt+D 또는 Ctrl+L을 눌러 주소 창으로 이동함.

    %USERPROFILE%

project 폴더에서 Claude 실행하기

  1. project 폴더로 들어가기: 홈 디렉터리로 돌아가 「project」 폴더를 엶.
  2. 실습에 쓸 PDF와 한글 또는 워드 문서가 보이는지 확인함.
  3. 선택된 파일이 있으면 Ctrl+Space로 해제하고 초점을 파일 목록에 둠.
  4. 팝업 키 또는 Shift+F10으로 현재 폴더의 메뉴를 엶.
  5. 터미널에서 열기를 선택함(Alt+T가 안내되면 그 키 사용).
  6. 위치 확인 후 실행하기: PowerShell 프롬프트에 project 폴더 경로가 표시되는지 확인하고 claude를 입력함.
  7. 첫 파일 지시 보내기: 폴더 신뢰 확인을 마친 뒤 Claude 입력창에 다음을 보냄.

자주 쓰는 폴더 고정하기

초점 되찾기와 탭 전환

  • 영역 이동: 위치를 놓치면 F6으로 탐색 창·파일 목록 등 주요 영역을 순환함.
  • 새 탭: Ctrl+T로 한 창에 여러 폴더를 엶.
  • 다음·이전 탭: Ctrl+Tab, Ctrl+Shift+Tab을 누름.
  • 현재 탭 닫기: Ctrl+W(마지막 탭이면 창이 닫힘).

파일 경로를 복사해 지시하기

  • 특정 파일을 지시하려면 탐색기에서 Ctrl+Shift+C로 경로를 복사해 입력창에 붙여넣음.
  • Ctrl+Shift+C는 센스리더의 「입력 문자 읽기 방법 설정」과 겹치므로 기능키 무시(Ctrl+Shift+N)를 한 번 누른 뒤 누름.
  • 기능키 무시(Ctrl+Shift+N): 다음에 누르는 키 한 번을 센스리더가 처리하지 않고 프로그램에 넘김. 가상 커서 상태에서는 동작하지 않음.

  • docparse는 문서를 진단해 파서를 고르고 여러 결과를 대조해 마크다운으로 만듦.
  • 텍스트가 있는 15쪽 이하 PDF는 Gemini 파서로 처리하며 무료 티어 안에서 쓸 수 있음.
  • 한글(HWPX)·워드·엑셀과 괘선 표를 추출하는 PDF는 무료 로컬 파서로 처리함.
  • 원본 파일이 따로 있으면 그것을 읽음: 배포용 PDF의 원본인 한글·워드 파일이 있으면 원본을 파싱하는 편이 정확함.
  • 원본에는 표의 칸 구조와 제목 단계가 남아 있어 파서의 추측이 줄어듦.
  • docparse는 PDF를 받으면 원본 파일이 있는지 먼저 확인함.

  • 폴더 구성이 바뀌면 작업 후 설명을 갱신함.

스킬과 파일을 내 컴퓨터에 두는 이유

  • 스킬, 규칙 파일, 업무 파일이 내 컴퓨터 폴더에 있으면 다른 에이전트로 옮기거나 폴더째 복사할 수 있음.
  • 앱 안의 클라우드 기능에 쌓은 자료는 그 서비스에서만 쓸 수 있음.
  • 설정과 스킬은 컴퓨터마다 한 번씩 설치함.

  • 설치 중 내 컴퓨터의 폴더 동기화를 묻는 항목은 개인 파일이 업무 드라이브로 올라가지 않도록 확인하고 고름.

  • 턴과 세션: 지시문 하나와 그 응답을 턴, claude를 실행해 종료할 때까지 이어지는 대화를 세션이라고 함.
  • 슬래시 명령: /로 시작하며 정해진 기능을 실행하는 입력 방식임.
  • 터미널에는 버튼이 없으므로 대부분의 설정을 슬래시 명령으로 바꿈.
  • 모델: Opus는 Claude 구독의 기본 모델임.
  • 추론 수준: 모델이 답하기 전에 생각하는 정도이며 Opus의 기본값은 medium임. 대부분의 문서 업무는 Opus의 medium으로 충분함.
  • 권한 모드: Claude가 파일을 바꾸거나 명령을 실행하기 전에 물을지를 정함. 계획 모드에서는 파일을 바꾸지 않고, 탐색과 계획을 더 많이 함.
  • 훅(Hook): 특정 시점에 스크립트를 실행하는 장치이며, agent-cli-tts-summary 스킬에서는 응답 후 요약 음성을 재생함.

터미널 입력에서 자주 막히는 곳

  • 입력이 되지 않을 때: 화면에 선택지 질문이 떠 있는지 확인하고 답함.
  • 답변 언어: 처음 화면은 영어로 나오지만 한국어로 입력하면 한국어로 답함.
  • 위쪽 방향키: 입력창에서 누르면 이전에 입력한 지시문이 불려 옴.
  • 불려 온 내용이 있으면 아래쪽 방향키를 눌러 빈 입력줄로 돌아오거나, 입력줄의 글자를 모두 지운 뒤 입력함.
  • 아래쪽 방향키로 진행 상황 화면이 열리면 Esc를 한 번 누름. Esc는 진행 중인 작업을 멈출 수 있으므로 화면을 먼저 확인함.
  • 화면 상황 묻기: Alt+PrintScreen으로 현재 창을 캡처하고, Claude 입력창에서 Alt+V로 붙여넣은 뒤 질문함.
지금 이 화면이 어떤 상황인지 확인하고, 다음에 무엇을 하면 되는지 알려 줘.
  • 캡처했다는 안내 음성은 나오지 않음.
  • 터미널에서 이미지 붙여넣기는 Ctrl+V가 아니라 Alt+V임.

TTS 요약 음성 속도를 7로 바꿔 줘.

TTS 음성 요약 꺼 줘.
명령 하는 일
/tts 현재 설정 확인
/tts speed 7 속도 변경: 1(가장 느림)~10(가장 빠름), 5가 보통, 소수점 가능(예: 7.5)
/tts off, /tts on 음성 요약 끄기와 켜기
/tts verbosity 1 요약 분량 변경: 1은 1~2문장, 2는 3~6문장(기본값), 3은 7문장 이상
/tts interim on, /tts interim off 질문 선택지와 중간 진행 보고도 읽을지 정함(Windows 기본값은 끔)
/tts-replay 직전 요약 음성 재생(새로 만들지 않으므로 비용 없음)

  • 명령이 기억나지 않으면 Claude에게 물음.
TTS 음성 요약에 쓸 수 있는 슬래시 명령을 알려 줘.
  • 속도는 바꾼 직후 응답부터, 요약 분량은 그다음 응답부터 적용됨.

  • 요약 생성에는 토큰이 추가로 사용됨.
  • 음성이 나오지 않으면 훅 설정의 진단을 요청함.

  • GitHub는 코드와 파일을 올려 두는 온라인 보관소임. 구글 드라이브에 문서를 보관하듯 GitHub에 코드를 보관함.

  • 올리기와 가져오기: 구글 드라이브와 달리 자동으로 올라가지 않음. 올릴 시점을 정해 변경 내용을 기록하고 GitHub로 보내며, 다른 기기에서는 그 내용을 가져옴.
  • 올리기와 가져오기는 Claude에게 요청함.
  • 저장소는 공개와 비공개 중에서 고름. 공개 저장소는 누구나 내용을 볼 수 있음.
  • 개발 중이거나 혼자 쓸 것은 비공개로 둠. 무료 계정에서 웹 페이지로 배포하려면 저장소를 공개로 해야 함.

  • 풀: GitHub에 올라간 내용을 내 컴퓨터로 가져옴. 다른 컴퓨터에서 이어 쓸 때 먼저 함.
  • 클론: GitHub의 저장소를 통째로 내 컴퓨터에 복사함.

세 가지 쓰임

  1. 여러 기기에서 이어 쓰기: 집 컴퓨터에서 올린 스크립트와 스킬을 직장 컴퓨터에서 가져와 이어서 씀.
  2. 다른 사람과 공유하기: 저장소 주소를 알려 주면 상대가 그 내용을 가져감. 스킬 번들 skills-for-the-blind도 저장소 주소로 설치함( 참조).
  3. 웹 페이지로 배포하기: 저장소에 올린 HTML 파일을 주소 하나로 여는 웹 페이지로 만듦.
  • 보관이 본래 용도이고 배포는 덧붙은 기능임.
  • 화면을 HTML로 만든 앱은 서버를 따로 마련하지 않아도 이 기능만으로 다른 사람에게 주소를 전달할 수 있음.
  • 더 복잡한 앱은 Vercel 같은 배포 서비스를 저장소와 연결함. 한 번 연결하면 저장소에 올릴 때마다 웹 페이지가 자동으로 갱신됨.

gh CLI

  • gh CLI: 터미널에서 GitHub 계정과 저장소를 다루는 도구임.
  • 인증을 한 번 마치면 Claude가 저장소 만들기와 웹 페이지 배포 설정은 gh CLI로, 올리기와 가져오기는 Git으로 처리함. GitHub 웹 화면을 직접 조작할 일이 줄어듦.
  • Claude는 gh CLI 사용법을 알고 있어 따로 플러그인을 설치하지 않아도 「이 폴더를 GitHub에 올려 줘」 같은 요청을 처리함.
  • gh CLI 인증은 Git에도 함께 적용됨.
  • 브라우저에서 GitHub에 로그인한 것과 gh CLI 인증은 별개임.

  • 스크립트: 컴퓨터가 할 일을 순서대로 적은 코드 파일임. 정해진 처리만 담으면 같은 입력에 같은 결과를 냄.
  • 스킬: 작업 절차와 판단 기준을 적은 SKILL.md에 스크립트와 참고 자료를 함께 묶은 폴더임. Claude가 읽고 상황에 맞게 수행함.
  • 앱: 사람이 화면에서 직접 조작하는 프로그램임. HTML로 만든 앱은 브라우저에서 주소로 엶.

스크립트도 문서임

  • 스크립트는 Python, JavaScript 같은 언어로 쓴 텍스트 파일임. CLAUDE.md, SKILL.md처럼 메모장으로 열어 읽을 수 있음.
  • 확장자로 언어를 구분함. Python은 .py, JavaScript는 .js임.
  • 연극 대본처럼 컴퓨터가 읽고 적힌 순서대로 실행함. 「이 입력이 오면 이렇게 처리한다」는 갈림길까지 모두 적어 둠.
  • 앱은 수많은 스크립트에 이미지, 소리, 데이터 같은 요소를 더한 것임.

앱의 종류와 접근성

  • 웹 앱: 브라우저에서 여는 앱임. 이 과정에서 만드는 앱은 모두 HTML로 만든 웹 앱임.
  • 데스크톱 앱: Windows나 macOS에 설치해 쓰는 앱임.
  • 모바일 앱: iPhone이나 Android용으로 그 기기의 언어로 따로 만드는 앱임. 카카오톡처럼 기기마다 설치하는 앱이 이 방식임.
  • 웹 앱에 PWA 지원을 더하면 휴대폰 홈 화면이나 컴퓨터 바탕 화면에서 바로 열림. 웹 앱을 감싸는 포장이며 모바일 앱으로 바뀌는 것은 아님.
  • 데스크톱 앱과 모바일 앱은 접근성을 따로 지시해야 함. 지시가 없으면 스크린 리더로 쓰기 어려운 앱이 나올 수 있음.
  • 웹 앱은 웹 콘텐츠 접근성 지침(WCAG)에 맞춰 달라고 하면 대체로 잘 만듦. 다만 읽어 주는 요소가 지나치게 많아지기 쉬우므로 불필요한 ARIA 속성(스크린 리더에 덧붙여 알려 주는 속성)은 빼 달라고 함.
  • 화면 요소의 이름을 알면 요청이 쉬워짐. 예: 제목, 목록, 접었다 펼치는 아코디언, 이전·다음 버튼.
  • 효과음, 게임 엔진처럼 앱에 쓸 외부 도구는 CLI나 API를 제공하는 것으로 찾아 달라고 함. Claude가 터미널에서 직접 다룰 수 있음. 가져온 효과음이 어울리는지는 직접 들어 보고 고름.

스킬과 앱 안의 스크립트

  • 스킬 안의 스크립트: 판단이 필요한 부분은 Claude가 맡고, 정해진 처리는 스크립트를 실행해 끝냄. hwpx-automation 폴더의 hwpx_edit.py가 한글 문서를 읽고 고치는 스크립트임.
  • 스킬 폴더의 일반적인 구성은 다음과 같음. 스킬마다 폴더 이름과 구성은 조금씩 다름.
    • SKILL.md: 전체 작업 흐름과 Claude가 판단할 기준을 적음.
    • scripts 폴더: 정해진 처리를 하는 스크립트를 모아 둠.
    • references 폴더: 필요할 때만 읽는 참고 자료를 모아 둠.
  • SKILL.md만 있는 스킬도 한 번 가 본 길을 다시 헤매지 않게 해 줌. 복잡한 스킬일수록 스크립트가 들어가야 강력해짐.
  • Claude가 판단하는 부분이 많을수록 잘못 처리할 가능성도 커짐. 정해진 데이터를 옮기거나 계산하는 일은 스크립트에 맡김.
  • 앱 안의 코드: 버튼을 누르면 실행되는 코드도 정해진 대로 처리한다는 점에서 스크립트와 같음.
  • 스크립트는 Claude가 작성하므로 코드를 직접 쓸 필요는 없음. 어느 부분을 스크립트로 만들지 정해 요청함.
  • 한 번만 하면 되는 처리는 스크립트로 남기지 않고 Claude에게 바로 요청함.
  • 스크립트 안에서 AI API를 불러 판단이 필요한 단계만 AI에 맡길 수도 있음. 예를 들어 이메일을 모으는 일은 스크립트가 하고 요약만 Claude API가 함. 이때는 API 키와 사용료가 필요함.

  • 처음부터 깨지지 않게 하려면 업무 폴더의 CLAUDE.md에 규칙으로 둠.

    CSV 파일은 항상 UTF-8 BOM 형식으로 저장한다는 규칙을 CLAUDE.md에 추가해 줘.

  • 다른 AI에서 코드를 내려받을 때도 음성 파일 없이 코드만 받았을 수 있음.
  • HTML이 가리키는 폴더 구조 그대로 파일을 함께 올려야 함. gh CLI를 쓰면 Claude가 폴더째 올림.
    이 앱이 쓰는 음성과 이미지 파일이 폴더에 모두 있는지 확인하고, 빠진 파일은 다시 만들어 줘. 그다음 폴더 전체를 저장소에 올려 줘.

Q. ChatGPT와 Claude는 무엇이 다른가.

  • 코딩 성능: 가장 큰 차이임.
  • 응답 방식: Claude는 방법을 여러 가지 제시하고 선택하게 하며 응답이 긴 편임. 과정을 투명하게 보여 줘 배우며 쓰기 좋음.
  • ChatGPT는 기본이 결과 위주의 짧은 보고임. 빠르고 편하지만 중간에 무엇을 했는지 확인하기 어려워 코딩할 때 다시 물어야 하는 경우가 생김.
  • ChatGPT도 요청하면 과정을 더 보여 줌. 대화 모드는 거의 안 보여 주고, 작업 모드는 중간 정도, Codex는 더 많이 보여 줌.
  • 복잡한 지시: 단계가 많은 스킬을 실행하면 Claude Opus가 가장 충실히 따르는 편임.
  • 기억: ChatGPT는 휴대폰 앱에서 기억을 잘 활용함. Claude는 컴퓨터에 저장된 대화 기록을 바탕으로 맥락을 잘 따르는 편임.
  • 코딩을 하지 않으면 월 20달러 요금제에서는 큰 차이가 없음. ChatGPT는 요금제에 따라 쓰는 모델이 달라 설명의 상세함 차이가 큼.

1. Claude 계정 로그인

Claude Pro 계정으로 로그인합니다. 무료 플랜에서는 실습에 쓸 Code 탭과 Claude Code가 열리지 않으므로 플랜을 먼저 확인해 주세요.

2. Claude Desktop 앱 설치

아래 주소에서 Windows용 앱을 내려받아 설치합니다.

https://claude.ai/download

확인: 앱을 실행해 좌측 사이드바에 코드 항목이 있는지 봅니다. 코드 항목이 보이면 1번과 2번이 함께 확인된 것입니다.

3. Git 설치

Code 탭을 처음 열면 Git 설치 안내 대화상자가 자동으로 뜹니다. 대화상자 안의 Git 다운로드 버튼을 누르고, 내려받은 설치 파일을 실행해 모든 화면에서 기본 설정 그대로 Next 또는 Install을 눌러 끝까지 설치합니다.

「나중에」 버튼을 누르지 마세요. Git 없이 진행되어 다음 단계가 막힙니다.

설치가 끝나면 앱을 완전히 종료한 뒤 다시 실행합니다. Claude 앱은 창을 닫아도 백그라운드에 남으므로 작업 관리자로 끕니다.

  1. Ctrl+Shift+Esc로 작업 관리자를 엽니다.
  2. 가상 커서를 해제하고 목록을 내려가 Claude를 찾습니다.
  3. 팝업 키를 누르고 Alt+E를 눌러 작업을 끝냅니다.
  4. Windows 키를 눌러 검색창에 「클로드」를 입력하고 다시 실행합니다.

작업 관리자 조작이 번거로우면 컴퓨터를 껐다 켜도 됩니다.

확인: 다시 실행한 뒤 Code 탭으로 돌아와 하단 입력창에 아래 문장을 그대로 붙여넣고 보냅니다.

Git 설치를 마쳤는데 제대로 설치된 것인지 확인해 줘.

Claude가 확인을 위해 PowerShell 명령을 실행하겠다며 권한을 묻습니다. 항상 허용을 누르세요. 설치가 확인됐다는 답이 오면 된 것입니다.

환경 변수를 설정해야 한다는 안내가 나오면 시스템 설정 창을 직접 건드리지 마시고 입력창에 아래 한 줄을 보내세요.

PowerShell로 환경 변수를 영구 설정하는 방법으로 네가 바로 해 줘.

환경 변수 설정이 끝나면 위와 같은 방법으로 앱을 한 번 더 종료하고 다시 실행합니다.

5. 홈 디렉터리에 project 폴더 만들기

홈 디렉터리에 폴더를 하나 만들고 이름을 「project」로 붙입니다. Windows에서 홈 디렉터리는 C:\Users\<본인 계정 이름>이며, 파일 탐색기에는 「사용자」 폴더 아래 본인 계정 이름으로 표시됩니다. 파일 탐색기에서 Alt+D로 주소창에 이동해 %USERPROFILE%을 입력하고 Enter를 누르면 바로 열립니다.

project 폴더 안에는 다음 두 파일을 넣어 주세요.

  • 업무에서 받은 PDF 문서 한 개(공문, 안내문, 보고서 등)
  • 업무에서 다루는 한글 문서 한 개(한글 문서가 없으면 워드 문서)

이름·연락처·주민등록번호 같은 개인정보가 들어 있지 않은 문서로 골라 주세요.

1회기에 Claude에서 이 폴더를 처음 고르면 폴더를 신뢰할지 묻는 화면이 뜹니다. 신뢰 버튼을 누르셔야 그 폴더의 파일을 읽습니다.

키는 비밀번호와 같습니다. 다른 사람과 공유하지 마시고, 화면에 띄워 둔 채 자리를 비우지 마세요.

7. 업무 폴더 하나 정하기

3회기부터는 project 폴더가 아니라 본인 업무 자료가 있는 폴더에서 실습합니다. 그 폴더 하나를 정해 주세요.

  • 업무 자료를 모아 두는 폴더면 가장 좋습니다. 정리가 안 돼 있어도 괜찮습니다.
  • USB 안의 폴더는 피해 주세요. 뽑으면 경로가 사라지고 드라이브 문자도 바뀝니다. C 드라이브로 옮겨 두고 쓰시는 편이 낫습니다.
  • 회사 컴퓨터에만 자료가 있으시면 실습에 쓸 컴퓨터의 문서 폴더 아래에 폴더를 하나 만들고, 개인정보가 없는 자료만 옮겨 주세요.

확인: 그 폴더의 경로를 적어 두시면 됩니다. 파일 탐색기에서 그 폴더에 포커스를 두고 Ctrl+Shift+C를 누르면 경로가 복사됩니다. 센스리더에서는 이 키가 센스리더 기능과 겹치므로 기능키 무시(Ctrl+Shift+N)를 한 번 누른 뒤 Ctrl+Shift+C를 누르세요.

8. 자동화하고 싶은 업무 하나 정하기

매주 반복하거나 시간이 많이 드는 업무 하나를 골라 주세요. 그 업무에 쓰는 자료(개인정보가 없는 것)를 7번의 업무 폴더에 넣어 두시면 3회기에 그 자료로 실습합니다.

9. GitHub 계정 만들기

GitHub는 코드와 파일을 올려 두는 서비스입니다. 3회기부터 만든 결과물을 보관하고 공유하는 데 씁니다.

  1. 브라우저에서 아래 주소를 엽니다.
https://github.com/signup
  1. 이메일, 비밀번호, 사용자 이름을 입력합니다. 사용자 이름은 공개 주소에 그대로 들어가므로 영문 소문자로 짧게 지어 주세요.
  2. 사람 확인 단계가 나오면 오디오 인증을 고릅니다. 음성 안내를 듣고 질문에 맞게 답을 입력합니다.
  3. 이메일로 온 인증 번호를 입력합니다.

확인: 브라우저에서 GitHub에 로그인된 상태면 된 것입니다. 이 브라우저를 10번에서 다시 씁니다.

10. gh CLI 설치와 인증

gh CLI는 터미널에서 GitHub를 다루는 도구입니다. 한 번 인증해 두면 저장소를 만들고 파일을 올리는 일을 Claude가 대신합니다. 브라우저에서 GitHub에 로그인했더라도 gh 인증은 따로 해야 합니다.

설치

  1. Windows 키를 누르고 wt를 입력한 뒤 Enter를 눌러 Windows Terminal을 엽니다. Claude를 실행하지 않은 PowerShell 상태에서 진행합니다.
  2. 아래 명령을 입력합니다.
winget install GitHub.cli

약관 동의를 물으면 Y를 입력하고 Enter를 누릅니다. 관리자 권한 확인 창이 뜨면 허용합니다. winget을 찾지 못한다는 오류가 나오면 아래 주소에서 Windows용 설치 파일을 내려받아 실행하세요.

https://cli.github.com
  1. 설치가 끝나면 exit를 입력해 터미널을 닫고 새로 엽니다. 설치 전에 열어 둔 터미널은 gh 명령을 인식하지 못할 수 있습니다.
  2. 아래 명령으로 설치를 확인합니다. 버전이 나오면 설치된 것입니다.
gh --version

인증

  1. 아래 명령을 입력합니다.
gh auth login --clipboard
  1. 질문이 몇 가지 나옵니다. 묻는 순서는 gh 버전에 따라 다를 수 있으니 질문 내용을 듣고 아래 표에서 답을 찾으세요. 센스리더 키패드로 화면을 읽고, 일반 방향키로 항목을 고른 뒤 Enter로 확정하세요. 원하는 항목이 이미 선택돼 있으면 Enter만 누르면 됩니다. Y로 답하는 질문은 Y를 입력하고 Enter를 누릅니다.
질문 고를 항목
사용할 서비스 GitHub.com
Git 연결 방식 HTTPS
Git에도 GitHub 계정 인증을 쓸지 Y
로그인 방법 Login with a web browser
  1. 터미널에 일회용 인증 코드가 나오고 클립보드에 자동으로 복사됩니다. 메모장에 붙여넣어 코드가 들어왔는지 확인해 두세요. 복사되지 않았으면 키패드로 코드가 있는 줄을 읽은 뒤 센스리더의 Insert+X로 복사해 메모장에 붙여넣고, 코드만 골라 다시 복사합니다.
  2. 터미널로 돌아와 Enter를 누릅니다. 브라우저가 열리지 않거나 GitHub에 로그인하지 않은 브라우저가 열리면, 9번에서 로그인한 브라우저에 아래 주소를 직접 입력하세요.
https://github.com/login/device
  1. 표시된 계정이 본인 계정인지 확인하고 계속 진행합니다.
  2. 가상 커서를 끄고 코드 입력란의 첫 칸에 코드를 붙여넣습니다. 나머지 칸이 채워지지 않으면 한 글자씩 입력합니다.
  3. 접근 권한을 승인합니다. 완료 메시지가 나오면 터미널로 돌아갑니다.

확인: 터미널에 아래 명령을 입력합니다. 본인 계정이 로그인 상태로 나오면 된 것입니다.

gh auth status

인증 코드가 만료됐다는 메시지가 나오면 터미널에서 Ctrl+C로 취소하고 gh auth login --clipboard부터 다시 하세요. 끝까지 되지 않으면 어디서 멈췄는지만 적어 두셨다가 3회기에 알려 주세요.

  • CLI: command line interface(명령 줄 인터페이스)의 약자.

  • Claude Code CLI는 터미널에서 명령으로 실행하는 에이전트임.

  • Windows 터미널에서 PowerShell이 열리면 claude를 입력해 Claude Code를 실행함.

  • PowerShell의 명령 입력과 Claude의 자연어 지시를 구분해야 함.

설치와 기본 설정 요청하기

  • Desktop 앱 Code 탭이나 사용 중인 에이전트에 다음을 보냄.
이 컴퓨터에 Windows 터미널과 PowerShell 7이 설치돼 있는지 확인해 줘. 없으면 설치하고, Windows 터미널을 기본 터미널 앱으로 설정해 줘. Windows 터미널의 기본 프로필은 PowerShell 7로 바꿔 줘.

Claude Code CLI를 공식 네이티브 설치 방식으로 설치해 줘. 이미 설치돼 있으면 설치 방식과 실제 실행되는 경로를 확인해 줘.
  • 네이티브 설치: 실행 파일을 직접 설치하며 자동 업데이트를 지원함.
  • 기본 터미널 앱: 명령 창을 열 앱을 정함.
  • 기본 프로필: 터미널 안에서 실행할 셸을 정함.
  • Windows PowerShell과 PowerShell 7은 별도 프로그램이므로 설치 후 기본 프로필도 확인함.
  • 중복 설치 안내가 나오면 실제 실행되는 Claude의 설치 방식과 경로를 확인하도록 요청함.

터미널에서 직접 실행하기

  1. Windows 키를 누르고 wt를 입력한 뒤 Enter를 누름(검색되지 않으면 Windows Terminal 검색).
  2. 키패드로 시작 화면을 읽어 PowerShell 7인지 확인함.
    • Windows PowerShell이면 에이전트에 기본 프로필 변경을 요청하고 터미널을 다시 엶.

  3. PowerShell에 다음을 입력해 홈 디렉터리로 이동함.

    cd ~

  4. PowerShell에 다음을 입력하고 Enter를 누름.

    claude

  5. 테마 선택이 나오면 원하는 화면 색상을 고름.

  6. Claude 구독 계정 로그인을 선택하고 브라우저에서 인증한 뒤 터미널로 돌아옴.
    • 이미 인증했다면 로그인 화면이 생략될 수 있음.
  7. 폴더 신뢰를 물으면 본인의 홈 디렉터리인지 확인하고 허용함(y/n 형식이면 y 입력 후 Enter).
  8. 모델명과 입력창이 나타나면 간단한 자연어 질문을 보내 응답을 확인함.
  • claude를 찾지 못하면: 터미널을 다시 열고, 그래도 안 되면 에이전트에 오류 문구를 전달함.
  • 앱 안에서만 실행됐다면: Windows 터미널을 직접 열어 위 절차를 진행함.

  • 터미널에서 Claude가 실행되면 Desktop 앱을 닫아도 됨.

  • 확인: Windows 터미널의 Claude에서 한국어 질문에 답을 받음.

  • 터미널의 테두리·진행 애니메이션은 키패드 탐색 시 불필요한 음성으로 낭독됨.

  • Claude Code의 스크린 리더 모드(axScreenReader)로 장식 문자를 줄일 수 있음.

클로드 코드 설정에서 스크린 리더 모드 켜 줘.
  • 「클로드 코드 설정에서」까지 입력함(생략하면 다른 접근성 설정과 혼동할 수 있음).
  • 고르라는 목록이 떴으면 목록에서 하나를 고르지 말고 위 문장을 그대로 다시 보냄.
  • 전역(Global) 설정으로 저장되므로, 한 번 켜 두면 터미널을 다시 열거나 다른 폴더에서 작업할 때도 유지됨.
  1. 터미널을 다시 열고 claude를 실행함.
  2. 시작 화면의 스크린 리더 모드 안내와 장식 문자 감소를 확인함.
  • 선택지는 번호와 항목을 먼저 읽고 번호 입력 후 Enter로 확정함.

입력창은 맨 아래에 있음

  • 입력창은 화면 맨 아래에 있고, 그 가까이에 권한 모드가 표시됨.
  • 센스리더가 위쪽 내용을 읽고 있다면 입력 전에 아래 화살표를 두어 번 누름.
  • 선택 목록에서는 화살표가 항목을 바꾸므로, 번호나 문자를 입력하고 Enter로 고름.

키패드로 지난 응답 읽기

  • 위아래 화살표 대신 Ctrl+넘패드 2로 맨 아래로 간 뒤 키패드로 위쪽 응답을 읽음.
  • 점자 디스플레이를 연결하면 빠르게 확인할 수 있음.

선택지 입력 후 Enter 누르기

  • 스크린 리더 모드에서는 숫자·y·n을 입력한 뒤 Enter로 확정함.
  • 입력 후 화면이 바뀌지 않으면 Enter를 눌렀는지 확인함.

Shift+Tab으로 권한 모드 바꾸기

  • Shift+Tab으로 권한 모드를 바꾸고 입력창 근처에서 현재 모드를 확인함.
  • 기본 모드(default), 편집 자동 승인(acceptEdits), 계획 모드(plan)를 선택할 수 있음.
  • 계정·설정에 따라 자동 모드(auto) 등이 추가됨.
  • 편집 자동 승인은 파일 편집을 허용하고, 자동 모드는 도구 실행을 검토해 허용 여부를 판단함.
  • 자동 모드에서도 작업이 멈출 수 있으므로 마지막 응답을 확인함.

작업 중 진행 줄의 반복 낭독 줄이기

  • 진행 줄이 반복 낭독되면 다음 중 하나로 줄임.

    • 다른 창에서 작업이 끝나기를 기다림.
    • 점자 디스플레이로 확인함.
    • 음성만 잠시 끔.

영어로 표시되는 작업 과정 읽기

  • 작업 과정이 영어로 길게 나오면 결과는 요약으로, 상세 과정은 키패드로 확인함.

터미널 창과 새 대화 열기

  • Ctrl+Shift+T로 새 탭을 엶(안 되면 Ctrl+Shift+숫자 1).
  • Ctrl+Shift+T는 센스리더의 「제목줄 읽기」, Ctrl+Shift+1은 「사용자 윈도우 읽기」와 겹치므로 기능키 무시(Ctrl+Shift+N)를 한 번 누른 뒤 누름.
  • 둘 다 안 되면 wt로 새 창을 엶.
  • 대화를 새로 시작하려면 /exit로 Claude Code를 종료한 뒤, PowerShell 프롬프트에서 claude를 다시 실행함.

홈 디렉터리와 설정 폴더 확인하기

  • 홈 디렉터리: 현재 Windows 사용자의 기본 폴더(C:\Users\[본인 계정 이름]).
  • 탐색기에서는 Users가 「사용자」로 표시될 수 있음.
  1. Windows 키+E로 파일 탐색기를 열고 내 PC, 로컬 디스크(C:), 사용자로 차례로 들어감.
  2. 공용이 아니라 본인 계정 이름의 폴더를 엶.
  3. 그 안에서 .claude 폴더를 찾음(맨 앞의 점 포함).
  4. .claude 안의 skills 폴더를 확인함(전역 스킬 설치 전에는 없을 수 있음).
  • [다른 방법] 주소 창에 입력하기: 1~2단계 대신 주소 창으로 바로 이동할 수 있음.
  1. 파일 탐색기에서 Alt+D 또는 Ctrl+L을 눌러 주소 창으로 이동함.

  2. 다음을 입력하고 Enter를 누름.

    %USERPROFILE%

  3. 본인 계정 이름의 폴더가 열리면 위 3단계부터 이어 감.

  • [팁] 설정 폴더로 바로 가려면 %USERPROFILE%\.claude를 입력함.

  • .claude: Claude Code의 사용자 설정과 관련 파일이 모이는 폴더임.

  • .claude\skills: 여러 작업 폴더에서 쓸 개인 스킬의 위치임.
  • 작업 폴더의 .claude\skills: 해당 프로젝트에서만 쓸 스킬의 위치임.

설정 폴더와 작업 폴더 구분하기

  • 작업 폴더: 읽거나 편집할 문서와 결과물을 모아 두는 곳이며, 이번 실습에서는 홈 디렉터리의 「project」 폴더를 사용함.
  • 파일 탐색기에서 작업 폴더를 열고 터미널을 실행하면 그 위치에서 Claude에게 일을 맡길 수 있음.

project 폴더에서 Claude 실행하기

  1. project 폴더로 들어가기: 홈 디렉터리로 돌아가 「project」 폴더를 엶.
  2. 실습에 쓸 PDF와 한글 또는 워드 문서가 보이는지 확인함.
  3. 선택된 파일이 있으면 Ctrl+Space로 해제하고 초점을 파일 목록에 둠.
  4. 팝업 키 또는 Shift+F10으로 현재 폴더의 메뉴를 엶.
  5. 터미널에서 열기를 선택함(Alt+T가 안내되면 그 키 사용).
  6. 위치 확인 후 실행하기: PowerShell 프롬프트에 project 폴더 경로가 표시되는지 확인하고 claude를 입력함.
  7. 첫 파일 지시 보내기: 폴더 신뢰 확인을 마친 뒤 Claude 입력창에 다음을 보냄.
    이 폴더에 어떤 파일이 있는지 읽고 정리해 줘.

  • 확인: 답변의 파일 이름과 탐색기의 파일 이름이 일치함.

  • 작업 폴더 밖의 접근까지 차단하려면 접근·실행 권한을 별도로 설정해야 함.

자주 쓰는 폴더 고정하기

  1. 파일 탐색기 열기: Windows 키+E를 누름.
  2. 고정할 폴더 선택하기: project 폴더의 상위 폴더로 이동해 목록에서 「project」 폴더를 선택함.
  3. 팝업 키 또는 Shift+F10을 눌러 즐겨찾기나 빠른 실행에 고정함(메뉴명은 Windows 버전에 따라 다름).
  4. Shift+Tab으로 왼쪽 탐색 창으로 이동함(원하는 영역이 아니면 F6으로 이동).
  5. 방향키나 첫 글자(영문 입력 상태에서 p)로 「project」를 찾아 Enter를 누름.
  6. Tab으로 파일 목록으로 돌아와 내용을 확인함.
  • [팁] 업무 폴더와 홈 디렉터리도 같은 방법으로 고정할 수 있음.

초점을 잃었을 때와 탭 전환하기

  • 영역 이동: 위치를 놓치면 F6으로 탐색 창·파일 목록 등 주요 영역을 순환함.
  • 새 탭: Ctrl+T로 한 창에 여러 폴더를 엶.
  • 다음·이전 탭: Ctrl+Tab, Ctrl+Shift+Tab을 누름.
  • 현재 탭 닫기: Ctrl+W(마지막 탭이면 창이 닫힘).

파일 경로를 복사해 지시하기

  • 특정 파일을 지시하려면 탐색기에서 Ctrl+Shift+C로 경로를 복사해 입력창에 붙여넣음.
  • Ctrl+Shift+C는 센스리더의 「입력 문자 읽기 방법 설정」과 겹치므로 기능키 무시(Ctrl+Shift+N)를 한 번 누른 뒤 누름.
  • 기능키 무시(Ctrl+Shift+N): 다음에 누르는 키 한 번을 센스리더가 처리하지 않고 프로그램에 넘김. 가상 커서 상태에서는 동작하지 않음.

TTS 요약 음성 속도를 7로 바꿔 줘.

TTS 음성 요약 꺼 줘.
명령 하는 일
/tts 현재 설정 확인
/tts speed 7 속도 변경: 1(가장 느림)~10(가장 빠름), 5가 보통, 소수점 가능(예: 7.5)
/tts off, /tts on 음성 요약 끄기와 켜기
/tts verbosity 1 요약 분량 변경: 1은 1~2문장, 2는 3~6문장(기본값), 3은 7문장 이상
/tts interim on, /tts interim off 질문 선택지와 중간 진행 보고도 읽을지 정함(Windows 기본값은 끔)
/tts-replay 직전 요약 음성 재생(새로 만들지 않으므로 비용 없음)
  • verbosity: 요약 음성의 분량을 정하는 설정이며 철자는 V, E, R, B, O, S, I, T, Y임.
  • 요약 음성이 거슬리면 먼저 /tts verbosity 1로 짧게 줄여 봄.
  • 명령이 기억나지 않으면 Claude에게 물음.
TTS 음성 요약에 쓸 수 있는 슬래시 명령을 알려 줘.
  • 속도는 바꾼 직후 응답부터, 요약 분량은 그다음 응답부터 적용됨.
  • 스크린 리더와 요약 음성이 겹치면 원하는 쪽만 사용하고 필요할 때 다시 켬.
  • 요약 생성에는 토큰이 추가로 사용됨.
  • 음성이 나오지 않으면 훅 설정의 진단을 요청함.

목소리 바꾸기

  • 기본 음성은 Windows 내장 음성이며 비용이 들지 않음.
  • 더 자연스러운 음성은 Gemini, ElevenLabs, Azure 중 하나의 API 키를 발급해 환경 변수로 등록한 뒤 바꿈.
  • 서비스마다 요금과 무료 사용량이 다름.
  • Azure는 무료 등급(월 50만 자)이 있고 숫자와 고유명사를 비교적 정확하게 읽음.
  • 키 등록 방법은 아래 「Gemini API 키 등록하기」와 같음.

  • 규칙 파일(CLAUDE.md): 폴더 설명과 공통 규칙을 적으며, 그 폴더에서 Claude를 시작할 때 읽음.
  • 스킬: 반복 작업의 절차를 SKILL.md에 적고 참고 자료와 실행 스크립트를 함께 둠.
  • 에이전트는 할 일이 스킬의 설명과 맞으면 해당 스킬을 사용함.
  • 스킬은 직접 만들거나 공개된 것을 설치할 수 있음.
  • 사용할 스킬을 명확히 지정하려면 이름과 할 일을 함께 입력함.
  • 홈 디렉터리의 .claude\skills: 어느 작업 폴더에서나 쓸 개인 스킬을 둠.
  • 작업 폴더의 .claude\skills: 그 폴더에서만 쓸 스킬을 둠.

작업 폴더 정하기

  • 이번 실습부터는 실제로 업무를 하는 폴더에서 Claude를 실행함.
  • 업무 폴더가 없으면 하나 만들고, 한글·PDF·텍스트 문서처럼 여러 형식의 파일을 넣어 둠.
  • 개인정보나 대외비가 있는 파일은 실습에 쓰지 않음.
  • 폴더 정리: 업무별로 하위 폴더를 나눠 두면 Claude가 파일을 빨리 찾고, 무엇을 바꿨는지 확인하기 쉬움.
  • [장점] 업무 폴더에서 실행하면 그 폴더가 맥락이 되므로 지시문이 짧아짐.
  • 예를 들어 홈 디렉터리에서는 「업무 폴더에서 회의 일정 파일을 찾아 알려 줘」라고 해야 하지만, 업무 폴더에서는 「이번 주 회의 언제야?」로 충분함.

  • Java: 설치돼 있으면 다른 변환기 결과와 대조하며, 없어도 변환되지만 검증되지 않은 상태로 표시됨.
  • 라이선스: python-hwpx는 비상업 라이선스이므로 영리 업무에서는 조건을 확인해야 함.

  • 저장소는 공개와 비공개 중에서 고름. 공개 저장소는 누구나 내용을 볼 수 있음.
  • 개발 중이거나 혼자 쓸 것은 비공개로 둠. 무료 계정에서 웹 페이지로 배포하려면 저장소를 공개로 해야 함.

알아 둘 용어

  • 커밋: 바뀐 내용을 내 컴퓨터의 저장소에 기록함. 아직 GitHub에는 올라가지 않음.
  • 푸시: 커밋한 내용을 GitHub로 올림.
  • 풀: GitHub에 올라간 내용을 내 컴퓨터로 가져옴. 다른 컴퓨터에서 이어 쓸 때 먼저 함.
  • 클론: GitHub의 저장소를 통째로 내 컴퓨터에 복사함.

세 가지 쓰임

  1. 여러 기기에서 이어 쓰기: 집 컴퓨터에서 올린 스크립트와 스킬을 직장 컴퓨터에서 가져와 이어서 씀.
  2. 다른 사람과 공유하기: 저장소 주소를 알려 주면 상대가 그 내용을 가져감. 스킬 번들 skills-for-the-blind도 저장소 주소로 설치함(1회기 실습 4 참조).
  3. 웹 페이지로 배포하기: 저장소에 올린 HTML 파일을 주소 하나로 여는 웹 페이지로 만듦.
  • 보관이 본래 용도이고 배포는 덧붙은 기능임.
  • 화면을 HTML로 만든 앱은 서버를 따로 마련하지 않아도 이 기능만으로 다른 사람에게 주소를 전달할 수 있음.
  • 더 복잡한 앱은 Vercel 같은 배포 서비스를 저장소와 연결함. 한 번 연결하면 저장소에 올릴 때마다 웹 페이지가 자동으로 갱신됨.

gh CLI

  • gh CLI: 터미널에서 GitHub 계정과 저장소를 다루는 도구임.
  • 인증을 한 번 마치면 Claude가 저장소 만들기와 웹 페이지 배포 설정은 gh CLI로, 올리기와 가져오기는 Git으로 처리함. GitHub 웹 화면을 직접 조작할 일이 줄어듦.
  • Claude는 gh CLI 사용법을 알고 있어 따로 플러그인을 설치하지 않아도 「이 폴더를 GitHub에 올려 줘」 같은 요청을 처리함.
  • gh CLI 인증은 Git에도 함께 적용됨.
  • 브라우저에서 GitHub에 로그인한 것과 gh CLI 인증은 별개임.

인증 상태 확인하기

  1. 업무 폴더에서 터미널을 열고 claude를 실행함(2회기 실습 7 참조).

  2. 인증 상태 확인을 요청함.

    gh CLI가 설치돼 있는지, 내 GitHub 계정으로 인증돼 있는지 확인해 줘. 인증이 안 돼 있으면 로그인은 시도하지 말고 상태만 알려 줘.

  3. 본인 계정이 로그인 상태로 나오는지 확인함.

  • 실습 14~16은 인증을 마치지 않아도 진행할 수 있음.
  • 인증을 마치지 못했다면 4회기 전에 마쳐야 함.

직접 인증하기

  • 인증은 Claude를 거치지 않고 터미널에 직접 입력하는 것이 가장 간단함.
  1. 터미널에서 Ctrl+Shift+N, Ctrl+Shift+T를 차례로 눌러 새 탭을 엶(1회기 [센스리더 팁] 참조). 터미널이 열려 있지 않으면 Windows 키를 누르고 wt를 입력해 엶. Claude를 실행하지 않은 PowerShell 상태에서 진행함.

  2. 아래 명령을 입력함.

    gh auth login --clipboard

  3. 질문이 몇 가지 나오면 질문마다 아래 답을 고름. gh 버전에 따라 묻는 순서가 다를 수 있음. 대부분 이미 선택돼 있어 Enter만 누르면 됨.

    • 사용할 서비스: GitHub.com
    • Git 연결 방식: HTTPS
    • Git에도 GitHub 계정 인증을 쓸지: Y
    • 로그인 방법: Login with a web browser
  4. 터미널에 일회용 인증 코드가 나오고 클립보드에 복사됨. 메모장에 붙여넣어 코드를 확인해 둠.
  5. 터미널에서 Enter를 누르면 브라우저에 GitHub 화면이 열림. 본인 계정을 확인하고 코드 입력란에 코드를 붙여넣은 뒤 접근 권한을 승인함.
  6. 터미널로 돌아와 gh auth status를 입력해 로그인 상태를 확인함.
  • 단계별 자세한 설명은 사전 준비 안내 10번 「인증」에 있음.

인증에서 막히는 곳

  • 명령을 입력했는데 웹 검색 결과가 뜨는 경우: Windows 검색창에 입력한 경우임. Windows 검색창에는 wt만 입력하고, 설치와 인증 명령은 열린 PowerShell에 입력함.
  • 설치했는데 gh 명령을 찾지 못하는 경우: 터미널을 닫고 새로 연 뒤 gh --version을 입력함.
  • PowerShell에 한국어 지시를 입력해 오류가 난 경우: 한국어 지시는 claude를 실행한 뒤 입력함. gh auth login --clipboard은 PowerShell에 직접 입력하는 명령임.
  • 선택 항목이 읽히지 않는 경우: 센스리더 키패드로 화면을 읽고 일반 방향키로 항목을 옮김. 선택 표시가 읽히지 않으면 센스리더 구두점 읽기 토글(Alt+Shift+Z)을 「모두 읽기」라고 들릴 때까지 누름. 인증을 마치면 같은 키로 원래 설정으로 되돌림.
  • 코드가 클립보드에 복사되지 않은 경우: 키패드로 코드가 있는 줄(First copy your one-time code)을 읽고 센스리더 Insert+X로 마지막 음성 출력 내용을 복사함. 메모장에 붙여넣어 코드만 남기고 다시 복사함.
  • GitHub에 로그인하지 않은 브라우저가 열린 경우: 로그인한 브라우저에 아래 주소를 직접 입력함.

https://github.com/login/device

  • 코드 입력란에 붙여넣기가 되지 않는 경우: 가상 커서를 끄고 첫 칸으로 이동해 붙여넣음. 나머지 칸이 채워지지 않으면 한 글자씩 입력함.
  • 인증 코드 오류나 만료 메시지가 나온 경우: PowerShell에서 Ctrl+C로 취소하고 gh auth login --clipboard을 다시 실행해 새 코드를 받음.
  • Claude가 인증 대기 중 시간 초과를 알린 경우: 별도 PowerShell에서 직접 인증하고 gh auth status로 확인한 뒤 Claude로 돌아감.
  • 어느 단계인지 알 수 없는 경우: Alt+PrintScreen으로 창을 캡처하고, 터미널 새 탭에서 claude를 실행해 입력창에 Alt+V로 붙여넣어 상황을 물음(2회기 「터미널 입력에서 자주 막히는 곳」 참조).

  • 스크립트: 컴퓨터가 할 일을 순서대로 적은 코드 파일임. 정해진 처리만 담으면 같은 입력에 같은 결과를 냄.
  • 스킬: 작업 절차와 판단 기준을 적은 SKILL.md에 스크립트와 참고 자료를 함께 묶은 폴더임. Claude가 읽고 상황에 맞게 수행함.
  • 앱: 사람이 화면에서 직접 조작하는 프로그램임. HTML로 만든 앱은 브라우저에서 주소로 엶.

스크립트도 문서임

  • 스크립트는 Python, JavaScript 같은 언어로 쓴 텍스트 파일임. CLAUDE.md, SKILL.md처럼 메모장으로 열어 읽을 수 있음.
  • 확장자로 언어를 구분함. Python은 .py, JavaScript는 .js임.
  • 연극 대본처럼 컴퓨터가 읽고 적힌 순서대로 실행함. 「이 입력이 오면 이렇게 처리한다」는 갈림길까지 모두 적어 둠.
  • 앱은 수많은 스크립트에 이미지, 소리, 데이터 같은 요소를 더한 것임.

스킬과 앱의 차이

구분 스킬 앱
쓰는 사람 나와 Claude Claude가 없는 사람도 씀
실행할 때 Claude 있어야 함 없어도 됨
처리 방식 Claude가 상황을 읽고 판단함 화면에 만들어 둔 기능만 수행함

  • 앱 안에는 Claude가 들어 있지 않음. 앱에 AI 기능을 넣으려면 API 키와 사용료가 따로 필요함.
  • 만든 스킬은 Claude 입력창에 /[스킬 이름]을 입력해 바로 실행할 수 있음. 스킬 이름은 스킬 폴더의 영문 이름임. 자연어로 요청해도 Claude가 맞는 스킬을 골라 씀.

앱의 종류와 접근성

  • 웹 앱: 브라우저에서 여는 앱임. 이 과정에서 만드는 앱은 모두 HTML로 만든 웹 앱임.
  • 데스크톱 앱: Windows나 macOS에 설치해 쓰는 앱임.
  • 모바일 앱: iPhone이나 Android용으로 그 기기의 언어로 따로 만드는 앱임. 카카오톡처럼 기기마다 설치하는 앱이 이 방식임.
  • 웹 앱에 PWA 지원을 더하면 휴대폰 홈 화면이나 컴퓨터 바탕 화면에서 바로 열림. 웹 앱을 감싸는 포장이며 모바일 앱으로 바뀌는 것은 아님.
  • 데스크톱 앱과 모바일 앱은 접근성을 따로 지시해야 함. 지시가 없으면 스크린 리더로 쓰기 어려운 앱이 나올 수 있음.
  • 웹 앱은 웹 콘텐츠 접근성 지침(WCAG)에 맞춰 달라고 하면 대체로 잘 만듦. 다만 읽어 주는 요소가 지나치게 많아지기 쉬우므로 불필요한 ARIA 속성(스크린 리더에 덧붙여 알려 주는 속성)은 빼 달라고 함.
  • 화면 요소의 이름을 알면 요청이 쉬워짐. 예: 제목, 목록, 접었다 펼치는 아코디언, 이전·다음 버튼.
  • 효과음, 게임 엔진처럼 앱에 쓸 외부 도구는 CLI나 API를 제공하는 것으로 찾아 달라고 함. Claude가 터미널에서 직접 다룰 수 있음. 가져온 효과음이 어울리는지는 직접 들어 보고 고름.

스크립트는 스킬과 앱에 함께 쓰이는 작업 단위

  • 스킬과 앱은 둘 중 하나를 고르는 대상이고, 스크립트는 어느 쪽을 고르든 그 안에 들어감.
  • 스킬 안의 스크립트: 판단이 필요한 부분은 Claude가 맡고, 정해진 처리는 스크립트를 실행해 끝냄. hwpx-automation 폴더의 hwpx_edit.py가 한글 문서를 읽고 고치는 스크립트임.
  • 스킬 폴더의 일반적인 구성은 다음과 같음. 스킬마다 폴더 이름과 구성은 조금씩 다름.
    • SKILL.md: 전체 작업 흐름과 Claude가 판단할 기준을 적음.
    • scripts 폴더: 정해진 처리를 하는 스크립트를 모아 둠.
    • references 폴더: 필요할 때만 읽는 참고 자료를 모아 둠.
  • SKILL.md만 있는 스킬도 한 번 가 본 길을 다시 헤매지 않게 해 줌. 복잡한 스킬일수록 스크립트가 들어가야 강력해짐.
  • Claude가 판단하는 부분이 많을수록 잘못 처리할 가능성도 커짐. 정해진 데이터를 옮기거나 계산하는 일은 스크립트에 맡김.
  • 앱 안의 코드: 버튼을 누르면 실행되는 코드도 정해진 대로 처리한다는 점에서 스크립트와 같음.
  • 스크립트는 Claude가 작성하므로 코드를 직접 쓸 필요는 없음. 어느 부분을 스크립트로 만들지 정해 요청함.
  • 한 번만 하면 되는 처리는 스크립트로 남기지 않고 Claude에게 바로 요청함.
  • 스크립트 안에서 AI API를 불러 판단이 필요한 단계만 AI에 맡길 수도 있음. 예를 들어 이메일을 모으는 일은 스크립트가 하고 요약만 Claude API가 함. 이때는 API 키와 사용료가 필요함.

사례: 강연 한 편에 쓰인 스크립트, 스킬, 앱

중학교 영어 수업용 학습 게임과 그 게임의 학생 설문 결과를 발표하는 강연의 준비 자료임.

  • 스크립트: 정해진 처리를 네 스크립트가 맡음.
    • 설문 응답을 내려받는 스크립트
    • 문항별 통계를 내고 보고서를 만드는 스크립트
    • 응답을 엑셀에서 열리는 표로 바꾸는 스크립트
    • 발표 화면의 제목을 내레이션 음성 파일로 바꾸는 스크립트
  • 설문 응답이 늘면 앞의 세 스크립트를 순서대로 다시 실행해 같은 형식의 결과를 얻음.
  • 스킬: 강연 원고와 발표 화면의 문장을 글 다듬기 스킬로 고침. 어느 표현을 어떻게 바꿀지는 Claude가 스킬의 기준을 읽고 판단하고, 금지한 기호가 남았는지 세는 검사는 스킬 안의 스크립트가 처리함.
  • 발표 화면에 넣을 문장은 판단의 영역이라 스크립트로 만들 수 없음. 그래서 원고를 먼저 글로 쓰고, 원고를 발표 화면으로 옮기는 절차를 스킬로 만들어 강연마다 씀.
  • 앱: 학생은 학습 게임을, 청중은 발표 화면을 각자 브라우저에서 주소로 엶. 둘 다 HTML로 만들어 GitHub에 올려 배포함.
